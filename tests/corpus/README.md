# Markdown 往返语料（tests/corpus）

每个 `.md` 文件都是一个用例：`npm run verify:corpus` 会把它喂进完整的 remark 流水线
（remark-parse + remark-gfm + 本项目三个自定义插件 `wikilink` / `tag` / `htmlInline`），
序列化后断言**逐字节等于原文**。

新增用例 = 往这个目录丢一个 `.md`。不需要写 JS。

## 语料必须写成「规范形式」

这里断言的是 **parse → serialize 的往返**，而不是「任何 Markdown 都能原样存回」。
remark 会把不规范的写法**正常化**，这些差异是上游行为、**不是本项目的缺陷**：

| 你写的 | remark 的正常化结果 |
| --- | --- |
| `- 项`（`-` 项目符号） | `* 项`（默认 bullet 是 `*`） |
| `---`（分隔线） | `***`（默认 rule 是 `***`） |
| `\| --- \|` 表格分隔行 | `\| -- \|`（按列宽取最小宽度并对齐） |
| 表格单元格 | 按最宽单元格补空格对齐 |
| `_强调_` | `*强调*` |
| setext 标题（下划线式） | ATX 标题（`#`） |
| 缩进代码块 | 围栏代码块 |

所以语料文件请**直接写成上表右列的形式**。跑一次 `npm run verify:corpus`，
它会指出第一处差异的位置（行 / 列 + 原文片段），照着改语料即可。

## 什么时候说明真的出问题了

以下情况属于**真缺陷**，不要改语料去迁就：

* 内容丢失（`[[A#锚点]]` 存盘后变成 `[[A]]`）——历史上真的发生过；
* 定界符被吞（`<kbd>` 变成空键帽、文字被甩到外面）；
* `#标签` 被吞掉或改名；
* 出现了语料里没有的字符。

如果某个构造确实无法保真且属于上游行为，在 `scripts/verify-corpus.mjs`
的 `EXPECTED_DIFF` 里登记并写明理由——**不要让门禁悄悄放过**。

## 与「未编辑文档一字不改」的关系

不冲突。未编辑的文档走保真层（原始文本直通），根本不经过 remark；
只有在编辑器里真正改动过、需要序列化时才走这条链路。
所以这里的「正常化」只作用于被编辑的文档，是被接受的行为。
