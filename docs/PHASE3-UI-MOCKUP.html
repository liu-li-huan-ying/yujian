玉笺性能模型与索引策略

本文档讨论 vault 在大规模笔记下的性能边界。与 Obsidian 不同，玉笺选择严格增量的索引维护策略，禁止任何遍历全库的周期任务。

当我们把 5000 个 Markdown 文件交给 vaultIndex.ts 时，索引内存应控制在 100MB 以内，输入延迟不应随文档增长而退化。这要求索引只存轻量元数据，不缓存正文、不索引全文。

设计原则：本地唯一真源。图床只是镜像，vault 永远是普通文件夹 + 相对路径资源。

双链与反向链接

中文排版渲染层
