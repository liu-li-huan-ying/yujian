## 1. 设计前提复核

### 1.1 沿用的三条设计原则（UI-DESIGN §1.1）

1. **内容优先**——界面低饱和、低对比，视觉权重让给正文。
2. **可预测**——相同操作在任何位置产生相同结果，不发明交互。
3. **克制的反馈**——高频静默操作不弹提示。

### 1.2 Phase 3 新增两条（因功能性质变化）

4. **常驻信息 vs 任务型分离。** Phase 3 引入大量面板，必须区分「写作者要一直看着的」（反链、标签、大纲）与「偶尔跑一次的」（自检、备份、lint、导出）。前者做成**可停靠的侧栏视图**，后者做成**按需唤起的浮层 + 命令面板入口**。混在一起是界面膨胀的根因。
5. **绝不污染编辑区。** 任何新增视觉（含中文排版的间距、标签/双链的颜色、CSS 片段）都不得破坏 UI-DESIGN §10.3 定下的编辑区纯净性——它是「直取 DOM 导出」所见即所得优势的前提。

### 1.3 材质分层（沿用 UI-DESIGN §10.2，Phase 3 的归属判定）

| 层   | Phase 3 新元素归属                                | 理由                       |
| --- | -------------------------------------------- | ------------------------ |
| 框架层（玉质） | **左栏各视图**（文件树/搜索/标签）、**右栏各视图**（大纲/反链）、状态栏 | 大面积常驻，静态渲染零开销           |
| 浮起层（玻璃） | 命令面板、临时编辑界面（表格/代码/公式）、自检/备份/lint/引文面板、**编辑器内 `[[` 补全**、冲突对照 | 小面积、临时，需表达「浮在内容之上」 |
| 内容层（纯净实色） | 编辑区（**含中文排版的视觉间距**）、**关系图谱画布**          | 见 §1.4                  |

### 1.4 两处易错判定（明确写死，避免实现时反复）

* **关系图谱用纯净实色底，不用玉质纹理。** 图谱由大量细线、小圆点与小字标签构成，任何纹理都会直接损害线条与文字的可辨识度——理由与 UI-DESIGN §10.3「编辑区必须纯净」完全一致。底色用 `--hue-editor`，节点与连线凭 `--hue-accent` / `--hue-text-2` / `--hue-text-3` 区分层级。
* **CSS 片段只作用于框架层与浮起层，绝不注入编辑区 DOM。** 否则会破坏导出一致性（UI-DESIGN §10.3 第三条），也会让用户自定义样式污染导出结果。实现上：片段样式挂在 `body` 但用 `:not(.milkdown *)` 作用域排除，或明确只挂到框架层根节点。

## 3. 信息架构：面板膨胀的解法（本节最关键）

### 3.1 问题

Phase 3 结束后，面板数量将从 7 个涨到 15+。若沿用「新增功能 = 新增一个常驻面板/标题栏按钮」的做法，标题栏会被塞满、快捷键不够用、用户找不到东西——**这正是 UI-DESIGN §5.8 已经批评过的 v1.0 标题栏问题，不能在 Phase 3 重演。**

### 3.2 解法：左右双栏「多视图切换」+ 任务型走命令面板

```
┌──────────────────────────────────────────────────────────────┐
│ 标题栏 38px  （保持三组图标不变，不新增常驻按钮）                          │
├──────────┬──────────────────────────────────┬────────────────┤
│ 左栏      │                                  │ 右栏            │
│ ┌──────┐ │                                  │ ┌────────────┐ │
│ │树 搜 标│ │            编辑区                 │ │大纲 反链     │ │
│ └──────┘ │                                  │ └────────────┘ │
│ 视图切换  │                                  │ 视图切换         │
│ 文件树    │                                  │ 大纲            │
│ (或搜索)  │                                  │ (或反链)        │
│ (或标签)  │                                  │                │
├──────────┴──────────────────────────────────┴────────────────┤
│ 状态栏 26px   字数 · 时长      ●已保存 · 告警标记 · 行列 · 编码        │
└──────────────────────────────────────────────────────────────┘
```

* **左栏**（文件树 / 搜索 / 标签）、**右栏**（大纲 / 反链）各自在栏顶加一组**视图切换 tab**（图标 + 文字，28px 高，选中态用 `--hue-active` 底 + `--hue-accent` 文字，与标题栏模式切换分段控件同款语言）。**同一时刻每栏只显示一个视图**——界面宽度不变、入口不增加。
* **任务型能力（自检 / 备份 / lint / 引文 / 静态站 / 图谱）不占常驻位置**，统一由命令面板唤起；其中会产生「持续告警」的（自检、lint）在**状态栏放一个小标记**（与已保存色点同款语言），点击才展开面板。
* **标题栏保持现状三组图标，一个都不加。**

> 这样 Phase 3 新增 8 个能力，但常驻入口只增加「左右两栏各一组 tab」这 2 处，标题栏零增长。

### 3.3 视图切换 tab 规格

| 项    | 规格                                                                     |
| ---- | ---------------------------------------------------------------------- |
| 容器   | 栏顶 30px（与现有面板表头同高），水平 `--hue-border-subtle` 下边框                        |
| 项    | 高 28px，padding `0 12px`，圆角 `--radius-md`，图标 14px + 文字 12px，间距 6px       |
| 图标   | 16×16 网格线性，`currentColor`，默认 `--hue-text-3`；悬停 `--hue-text-2`；选中 `--hue-accent` |
| 选中态  | `background: var(--hue-active)` + 文字/图标 `--hue-accent` + 底部 2px accent 横条 |
| 徽标   | 右栏「反链」tab 上显示引用数（11px，`--hue-text-3`，圆角 `--radius-sm` 底衬）              |
| 键盘   | `Ctrl+1/2/3` 切左栏，`Ctrl+Alt+1/2` 切右栏（可自定义）                               |
| 无障碍  | `role="tablist"` / `role="tab"` + `aria-selected`，左右方向键在 tab 间移动        |

### 3.4 ⚠️ 键位规划（先修一个现存不一致）

**现状核查（`src/App.vue` 实读）**：

| 键位             | 实际绑定           | UI-DESIGN 文档说法        |
| -------------- | -------------- | --------------------- |
| `Ctrl+F`       | ✅ 聚焦搜索（:268）   | §5.2 却写搜索框提示为 `Ctrl K` |
| `Ctrl+K`       | ❌ **未绑定**       | §5.6 / §7 称命令面板为 Ctrl+K |
| `F3`/`Shift+F3` | ✅ 上/下命中        | —                     |
| `F1`           | ✅ 帮助           | ✅ 一致                  |
| `Ctrl+\` / `Ctrl+Shift+\` | ✅ 侧栏 / 大纲 | ✅ 一致                  |
| `Ctrl+/`       | ✅ 模式切换         | ✅ 一致                  |

> **结论：搜索框显示的 `Ctrl K` 提示与实际绑定 `Ctrl+F` 不一致，属存量缺陷，Phase 3 一并修掉。**

**规划（对齐 VS Code 惯例，避免与查找冲突）**：

| 键位              | 用途              | 说明                                   |
| --------------- | --------------- | ------------------------------------ |
| `Ctrl+F`        | 全文搜索（本文档/全部）    | **保持不变**；顺带把搜索框提示从 `Ctrl K` 改为 `Ctrl F` |
| `Ctrl+K`        | **快速打开笔记**（新建用途） | 跳到任意 `.md`，符合「K = 跳转/链接」直觉，且让文档里已有的 Ctrl K 说法落地 |
| `Ctrl+Shift+P`  | **命令面板**        | 避开与 `Ctrl+F` 查找的冲突，符合行业惯例            |
| `Ctrl+Shift+F`  | 预留（全局替换）        | 现状替换入口在侧栏，暂不占用                       |

> 为什么不把命令面板放 `Ctrl+K`：搜索框已经显示了 `Ctrl K` 提示，若命令面板也用 `Ctrl+K`，用户按了会困惑（到底出搜索还是出命令面板）。让 `Ctrl+K` 专职「跳转笔记」、`Ctrl+Shift+P` 专职「命令」，职责单一且互不干扰。

### 3.5 命令面板规格（扩展 UI-DESIGN §5.6）

* 宽 560px，距顶部 15vh 居中，`.glass`；输入框 40px / 16px
* 结果行 36px，最多 9 条；分组标题 11px / `--hue-text-3` / 字间距 0.05em
* **Phase 3 新增分组顺序**：文件 · 视图 · 知识（双链/标签/图谱）· 工具（自检/备份/lint/引文）· 导出 · 设置
* 每项右侧显示**当前快捷键**（键位胶囊：底 `rgba(var(--hue-key), .16)` + 文字 `--hue-text-2`），无键位则不显示
* `↑↓` 选择、`Enter` 执行、`Esc` 关闭；支持模糊匹配
* 无障碍：`role="combobox"` + `aria-expanded` + `aria-activedescendant` 指向高亮项

## 4. 组件规格

### 4.1 反链面板（右栏视图）

```
┌─ 反链 ───────────────── 12 ─┐
│ ▾ 已链接（9）                 │
│  📄 electron-架构.md         │
│  …引用 `[[玉笺性能]]` 的三个…   │
│  📄 vite-版本锁定.md          │
│  …参见 `[[玉笺性能]]` 一节…     │
│ ▾ 未链接提及（3）          ⤴  │
│  📄 随笔.md                  │
│  …提到了「玉笺性能」但没加链接…  │
└───────────────────────────┘
```

| 项       | 规格                                                                                     |
| ------- | -------------------------------------------------------------------------------------- |
| 材质      | 玉质（框架层），与大纲面板完全一致                                                                      |
| 表头      | 30px，「反链」13px/500 + 右侧计数徽标（11px，`--hue-surface-2` 底 + `--hue-text-3`）                  |
| 分组      | 「已链接 / 未链接提及」两个可折叠组；组头 12px / `--hue-text-3` / 500，che-vron 10×10                       |
| 条目      | 文件名 13px / `--hue-text-1`，下方上下文 12px / `--hue-text-2` 单行截断；行 padding `8px 12px`         |
| 上下文高亮   | 命中词用 `rgba(var(--hue-mark), .22)` 底衬 + `--hue-text-1` 文字（**不用** accent，避免与选中态混淆；注意 `--hue-mark` 是 RGB 三元组，须 `rgba(var(...), α)`） |
| 未链接提及条  | 右端一个 24×24 图标按钮「包裹成双链」（`--hue-text-3` → hover `--hue-accent`），tooltip 说明               |
| 悬停/选中   | 悬停 `--bg-hover` 等效（用 `--hue-highlight`）；点击跳转并高亮命中行                                      |
| **空状态** | 图标 +「还没有笔记链接到这里」+ 一行次级说明（12px / `--hue-text-3`）；**不做插画**（UI-DESIGN §1.2）              |
| 加载      | 骨架行 2 条（`--hue-surface-2`，1s 循环淡入淡出，`prefers-reduced-motion` 时静态）                       |
| 无障碍     | 条目 `role="button"` + `tabindex`；`↑↓` 在条目间移动，`Enter` 跳转                                 |

### 4.2 标签面板（左栏视图）

| 项     | 规格                                                                                     |
| ----- | -------------------------------------------------------------------------------------- |
| 顶部    | 搜索/过滤框（28px，与现有搜索框同款），placeholder「过滤标签」                                               |
| 标签项   | 高度 28px；标签名渲染为玉质药丸芯片 `TagChip`（中性玉色渐变 + 1px 玉色描边 + 5px 圆角，`#` 用 `--hue-text-3`、标签名 `--hue-text-1`，与编辑器内联 `.yj-tag__label` 同族）；右侧计数 11px / `--hue-text-3` 推至右缘对齐 |

### 4.3 关系图谱

| 项      | 规格                                                                                          |
| ------ | ------------------------------------------------------------------------------------------- |
| 画布     | **Canvas 2D**，底 `--hue-editor`（纯净实色，无纹理，见 §1.4）                                             |
| 当前笔记节点 | 半径 8，`--hue-accent` 实底 + 白色/`--hue-on-accent` 描边 1.5px；带常驻标签                                |
| 一跳邻居   | 半径 5，`--hue-text-2` 填充；标签 11px                                                               |
| 二跳及更远  | 半径 3.5，`--hue-text-3` 填充，**默认不显示标签**（悬停才出），避免文字糊成一片                                          |
| 连线     | 1px，`rgba(--hue-text-3, .35)`；悬停节点时其连线提到 `--hue-accent` 60%                                  |
| 标签     | 11px / `--hue-text-2`，带 2px 同底色描边（`stroke`）保证压在连线上仍可读                                         |
| 控制条    | 浮于画布右上：本地子图/全局切换（分段控件，28px）、跳数 1/2/3、缩放 +-、适应窗口；全部 `.glass` 小胶囊                             |
| 交互     | 单击选中（高亮其邻居、淡化其余 60%）· 双击打开笔记 · 拖拽平移 · 滚轮缩放 · 拖节点可固定位置                                       |
| 性能护栏   | 默认 ≤300 节点，超出显示「当前显示 300 / 共 1280，切换本地子图以聚焦」提示条；tick 节流；`alpha` 衰减后停止计算                     |
| 无障碍    | Canvas 本身不可读 → **必须提供等价的列表视图**（「图谱 / 列表」切换），列表复用反链规格；键盘可操作列表                                  |
| 动效     | 力导收敛过程属功能性动画，`prefers-reduced-motion` 时**跳到收敛终态**（直接渲染静态布局，不做逐帧动画）                           |

### 4.4 复杂元素临时编辑界面（学 Typora）

> 目标：降低认知负荷——作者面对的是最终文档的「样子」，复杂元素提供专注的操作区，而不是让人在源码里数竖线。

**共用规格**：`.glass` 浮层，圆角 `--radius-lg`，padding 16px，阴影 `--hue-shadow-2`；`Esc` 关闭并应用、`点击外部` 应用并关闭；打开时对应块加 2px accent 外描边表示「正在编辑它」。

| 元素  | 内容                                                                                        |
| --- | ----------------------------------------------------------------------------------------- |
| 表格  | 顶部工具条：增删行列、增删表头、对齐方式（三档分段）、删除表格；**列宽直接拖拽调整**（列间 6px 热区，hover 显 accent 竖线）；底部一行「行列数」微标注 |
| 代码块 | 全宽专注编辑区（可展开为浮层），顶部语言下拉 + 复制按钮；行号可开关；**语法高亮与编辑区内完全一致**（避免割裂）                               |
| 公式  | 上半 LaTeX 源码输入（等宽 14px），下半实时预览；常用符号工具条（分 4 组，每组 ≤8 个）；底部显示 `\label` 与编号状态                |

**状态**：工具条按钮 28×28，默认 `--hue-text-3`、hover `--hue-text-1`、active `--hue-accent`、disabled opacity .4；危险操作（删除表格/列）用 `--hue-danger` 且需二次确认。

### 4.5 完整性自检 / 备份 / lint（任务型浮层）

三者**共用一套外壳**（与 `LinkCheckPanel` 同款，已验证好用）：

```
┌─ [图标] 标题 ────────── [计数] [重跑] [×] ─┐
│ [全部 12] [索引不一致 3] [孤儿快照 4] [缺附件 5] │  ← 过滤 chips，带计数
│  摘要行（12px / --hue-text-2）              │
├──────────────────────────────────────┤
│ 条目列表（图标 + 主文 + 次级路径 + 行内操作）       │
├──────────────────────────────────────┤
│                        [次要] [主要按钮]  │  ← 底部操作区
└──────────────────────────────────────┘
```

| 项      | 规格                                                                     |
| ------ | ---------------------------------------------------------------------- |
| 尺寸     | 宽 520px（含列表的复杂型，UI-DESIGN §5.7）；自检/备份可到 560px                          |
| 表头     | 与 `LinkCheckPanel` 完全一致（Icon 15px + 标题 13px/500 + 计数徽标 + 重跑 + 关闭）      |
| 过滤 chip | 28px 高，圆角 `--radius-md`；选中 `--hue-active` + `--hue-accent` 文字；chip 内带计数 |

## 5. 中文排版规格（批次四）

> 依据：W3C《中文排版需求》§3.2.2、GB/T 15834—2011。规范原文即指出「理想情况下该间距应由排版引擎自动加入，宽度为 ¼ em」——**这正是要做在渲染层的依据**。

| 项目       | 规格                                                                                        |
| -------- | ----------------------------------------------------------------------------------------- |
| 中英/中数间距  | 汉字与拉丁字母、数字之间自动补 **¼ em（0.25em）** 间隙；**渲染层实现，源文件不改**                                        |
| 实现方式     | 优先 CSS `text-spacing`（渐进增强）；不支持时用 ProseMirror Decoration 在边界插入零宽间隔元素。**必须验证导出不被污染**     |
| 与全角标点相邻  | 汉字/拉丁 与**全角标点**之间**不补**间距（规范明确）                                                            |
| 行内代码     | 前后补 ¼ em；紧邻全角标点时不补                                                                        |
| 中文强调     | **禁用斜体**：`em` 在中文语境改用 `--hue-accent` 颜色（或可选项「着重号」：字下 1px 圆点）。理由：中文斜体公认难看，规范亦建议以颜色/着重号替代 |
| 标点挤压     | 连续全角标点（如「」，）挤压至 0.5em；行首行尾全角标点挤压 50%（避头尾的基础）                                              |
| 避头尾      | 行首禁止出现 `。，、；：？！）》」』`；行尾禁止出现 `（（《「『`。用 CSS `line-break: strict` / `hanging-punctuation` 渐进实现 |
| 字体 fallback | 中文优先命中中文字体，拉丁与数字优先命中 `--font-mono` 栈中的西文字形，避免中文标点用西文字体渲染导致的字形错乱                            |
| 中文行高     | 正文行高维持 1.75（UI-DESIGN §3.2）；**中文段落间距比西文多 4px**，补偿全角标点的视觉密度                                   |

* **开关**：外观/偏好面板提供「中文排版优化」总开关 + 各子项开关，默认全开。
* **显式改写命令**（唯一允许改源文件的路径）：命令面板「排版规范化」——中英补空格、半角标点转全角、清除连续空格。走 `ConfirmDialog` 展示将改动多少处，可撤销。
* ⚠️ **红线**：保存时绝不自动改写源文件。

## 8. 五皮肤与明暗适配

* 全部新组件**只引用 `--hue-*` 令牌，禁止硬编码色值**——五套皮肤（青瓷/天青/月白/黛/琥珀）× 明/暗自动生效。
* **令牌核实结论（2026-09-01 逐条查 `src/styles/tokens.css`）**——实现时务必按此用法，勿凭印象：
  * 绝大多数 `--hue-*` 是 **hex 色值**，可直接用：`--hue-accent` / `--hue-text-1|2|3` / `--hue-editor` / `--hue-success` / `--hue-danger` / `--hue-on-accent`
  * `--hue-active` / `--hue-highlight` / `--hue-border-subtle` / `--hue-code` 是 **rgba()**，直接用
  * **`--hue-mark` / `--hue-key` 是 RGB 三元组**（如 `--hue-mark: 226,190,120`），必须写成 `rgb(var(--hue-mark))` 或 `rgba(var(--hue-mark), .22)`
  * **不存在 `--hue-warning`**。警告级严重度**复用琥珀色 `rgb(var(--hue-mark))`**（它本身就是随皮肤走的荧光笔迹色，语义吻合），不新增令牌；错误用 `--hue-danger`，成功用 `--hue-success`，提示用 `--hue-text-3`
  * `--hue-shadow-1|2` / `--hue-surface` / `--hue-surface-2` / `--hue-bar` 均存在，按原语义使用
* **图谱配色需逐皮肤校验**：月白（低饱和）皮肤下节点与连线对比度可能不足 → 实现时对每个皮肤跑一遍 §7 的 3:1 校验，不足则节点改用 `--hue-text-1`。
* 关系图谱底用 `--hue-editor`，随皮肤/明暗自动切换；**不叠加玉质纹理**（§1.4）。

## 9. 性能相关的设计约束

| 约束                              | 原因                                          |
| ------------------------------- | ------------------------------------------- |
| 图谱节点默认 ≤300，超出提示切本地子图           | 力导 tick 持续重排，大库必卡（Obsidian 实证）             |
| 图谱用 Canvas 不用 SVG               | 节点数多时 SVG DOM 会拖垮渲染                         |
| 反链/标签列表超 200 条时虚拟滚动             | 大库下长列表直接渲染会卡                                |
| 中文排版间距用 CSS/Decoration，不做逐字符测量 | 逐字符 JS 测量在长文档会拖慢输入延迟（违背「打字零延迟」护城河）        |
| 临时编辑界面关闭即销毁，不常驻                 | 避免同时存在多个 `backdrop-filter` 玻璃层（模糊开销显著）      |
| 自检/备份/lint 面板打开时才计算，不做后台周期扫描    | 禁止任何遍历全库的周期任务（防坑准则）                         |

## 10. 设计 QA 检查清单（每批完成前逐条过）

1. 是否复用了既有组件/规格，而没有发明第二套面板外壳？
2. 是否只使用 `--hue-*` 令牌（无硬编码色值）？
3. 材质分层是否正确（框架层玉质 / 浮起层玻璃 / 内容层纯净）？
4. 五个皮肤 × 明暗下是否都正常？对比度是否达标（正文 4.5:1、图形 3:1）？
5. 状态是否齐备（§6 九种）？空态与错误态是否都有？
6. 键盘是否可完成全部操作？焦点环是否可见？`role` / `aria-*` 是否正确？
7. `prefers-reduced-motion` 下是否无持续动画？
8. 200% 文本缩放下是否不破版？
9. 新界面是否污染了编辑区 DOM（导出一致性）？
10. 是否引入了新的常驻入口（应尽量避免，走命令面板）？
11. i18n 文案是否中英同步（`t.ui` 命名空间）？
12. 大样本下是否实测过（≥500 笔记 / ≥10 万字文档）？
