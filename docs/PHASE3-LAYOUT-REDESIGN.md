# Phase 3 功能按键布局重分布

> 状态：**已落地（2026-09-05）**——左缘活动栏 + 标题栏常驻工具按钮 + 状态栏语言按钮 + 精简「更多」。
> 轨道视图（`RailView`）方案**已废弃并移除**，原因见 §4。

## 1. 问题诊断

- 「更多 ⌄」菜单膨胀为 **14 项扁平长列表**，语义混杂（设置 / PKM 知识 / 编辑器动作 / 库安全 / 帮助）。
- 反链 / 标签 / MOC 这些 PKM 核心能力埋进二级菜单，快照 / 凝神却占着标题栏常驻开关——**高频与低频倒置**。
- 用户明确要求：**不要把什么东西都往「更多」里塞**，要把里面的东西**拆出来变成按钮，分散到界面四周**。

## 3. 浮层互斥（关键约束）

标签 / 内容地图 / 反链 / 快照 四个**玻璃浮层**由 `App.togglePanel()` 统一收口**互斥**：

- 任一时刻只显示一个浮层；
- 点当前已开的那个 → 收起；点另一个 → 替换（其余全关）；
- 快照打开时顺带 `snapshots.refresh` 拉取。

**为什么必须互斥**：多个 `position:absolute` 浮层并发叠在编辑区会互相压盖，正是上一版「面板切换失灵」的直接成因。互斥是数据层的收口，而非只靠样式。

## 4. 轨道视图（RailView）为何废弃

曾尝试「左右栏轨道视图 tab」把面板从浮层改为轨道一等公民（提交 `703c187`），**已整段 revert**：

1. **功能缺陷（直接成因）**：`RailView` 的内容槽里，基础视图（`<Sidebar>` / `<Outline>`）**始终渲染**，只有附加面板带 `v-if`。切到「标签」时文件树仍在，两面板在 `display:flex` 的槽里并排溢出 → 用户体感「面板切换失灵」。
2. **方向违背需求**：轨道 tab 与重排菜单一样是**「收拢」**，而用户要的是**「打散成按钮」**。把 6 个能力收进一条 tab 条，等于换个地方继续藏。

教训：**改布局前先确认需求是「收拢」还是「打散」**；收拢（菜单 / tab / 抽屉）与打散（常驻按钮）是相反方向，选错即全盘返工。
