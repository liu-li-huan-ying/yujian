## 3. 双栏 2×2 停靠布局（左右独立，可同屏）

四块 PKM 视图（标签 / 内容地图 / 反链 / 快照）不再以浮层形式弹出，而是**停靠**进左右两列的底部块，与顶部的基础视图（目录 / 大纲）上下并列：

```
┌─────────┬───────────────────────────┬─────────┐
│ 活动栏   │  左列            │  编辑区   │  右列           │
│ (44px)  │ ┌──────────────┐  │          │ ┌─────────────┐ │
│         │ │ 目录(文件树)  │  │          │ │ 大纲         │ │
│ 文件树   │ ├──────────────┤  │  Markdown │ ├─────────────┤ │
│ 标签     │ │ 标签/内容地图  │  │  正文     │ │ 反链/快照     │ │
│ 内容地图  │ └──────────────┘  │          │ └─────────────┘ │
│ 大纲     │   (左列 上下两块)   │          │  (右列 上下两块)  │
│ 反链     │                    │          │                 │
│ 快照     │                    │          │                 │
└─────────┴───────────────────────────┴─────────┘
```

驱动状态（在 `App.vue`，取代早期全局互斥的 `togglePanel`）：

- `leftBottom: 'none' | 'tags' | 'moc'` —— 左列底部块，由活动栏「标签 / 内容地图」切换；
- `rightBottom: 'none' | 'backlinks' | 'snapshot'` —— 右列底部块，由活动栏「反链 / 快照」切换；
- `sidebarVisible` / `outlineVisible` —— 左 / 右列顶部块（目录 / 大纲）可见性。

**左右两列各自独立、互不互斥**：点开左列「标签」+ 右列「反链」即可**同屏看到标签与反链**；恰好满足用户要的「类似 VS Code 双栏」体验，且**不牺牲「每栏单视图」**（每列每块仍只显一个视图，只是两列能同时开）。

**为什么不用浮层互斥 / 不用 Obsidian 单栏堆叠**：早期 `togglePanel` 全局互斥是为了避免多浮层叠压编辑区；但用户要的是「同屏多视图」，互斥反而挡路。Obsidian 式「单栏内竖向堆叠多个面板」会压窄每块、牺牲单视图——也比不上 VS Code 双栏。故采用双栏各显一视图、两栏并开的折中。

**停靠实现**：`App.vue` 新增 `.dock-col`（左右两列，flex 纵向 100% 高）+ `.dock-slot`（底部块容器）。四个玻璃面板（`.tags/.moc/.bl/.snap`）原本 `position:absolute` 浮层，经 `.dock-slot :deep(...)` 强制中和（`position:relative !important; width/height:100% !important; border-radius:0; box-shadow:none; animation:none`），成为填满停靠块的玉质面板，**零改面板源码**。右列大纲同样经 `:deep(.outline){width:100%}` 填满列宽。

## 4. 轨道视图（RailView）为何废弃

曾尝试「左右栏轨道视图 tab」把面板从浮层改为轨道一等公民（提交 `703c187`），**已整段 revert**：

1. **功能缺陷（直接成因）**：`RailView` 的内容槽里，基础视图（`<Sidebar>` / `<Outline>`）**始终渲染**，只有附加面板带 `v-if`。切到「标签」时文件树仍在，两面板在 `display:flex` 的槽里并排溢出 → 用户体感「面板切换失灵」。
2. **方向违背需求**：轨道 tab 与重排菜单一样是**「收拢」**，而用户要的是**「打散成按钮」**。把 6 个能力收进一条 tab 条，等于换个地方继续藏。

教训：**改布局前先确认需求是「收拢」还是「打散」**；收拢（菜单 / tab / 抽屉）与打散（常驻按钮）是相反方向，选错即全盘返工。2×2 停靠列是「打散为按钮 + 同屏多视图」的落地形态，与需求一致。
