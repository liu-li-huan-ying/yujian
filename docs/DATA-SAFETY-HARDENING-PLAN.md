> 状态：**S1~S6 已落地并随 v2.3.0 发布**（2026-10-04）｜ 测试 407 → **464 passed / 0 failed**
> 来源：2026-10-04 三路并行审计（写入与备份链路 / 索引与并发 / 破坏性操作与恢复），
> **P0/P1 关键条目已逐条读源码复核**，非采信转述。
> 核心原则（主人裁定）：**宁可打扰也不能静默**。

---

## 一、结论

既有安全网（原子写 + 自动备份 + 版本快照 + 损坏巡检）**设计水平很高**，
保真三态、`docPath` 锁定、删除走回收站、损坏回滚取「倒序第一份未损坏」等全部正确且有注释留痕。

真问题只有一个：**这些安全网自己失效时，全部是静默的。**

挖出 3 条 P0（可真实丢内容）+ 7 条 P1（崩溃/异常场景），全部已修或已排期。

## 二、两条长期架构约束（比任何单点修复都重要）

### 约束 1 · 保存路径的唯一实现是 `electron/main/safeWrite.ts`

任何新增写路径**必须调它**，不自己拼「读旧 → 备份 → 原子写」。

> 为什么：修复前 `ipc/files.ts`（保存）有完整安全网，而 `vault/search.ts`（批量替换）
> 是裸 `writeFile` —— 同一件事**两套安全等级**。收进单一原语后，
> 「两处实现漂移」从「可能」变成「结构上不可能」。
> 已由 `[Z3]` 静态门禁逐条钉死。

### 约束 2 · 索引的唯一真源是 watcher 维护的内存实时索引（`getLiveIndex`）

派生数据（反链 / `[[` 补全 / 未链接提及 / 标签 / MOC / 图谱 / 搜索）**一律走它**，
不得回读磁盘快照（`ensureIndex` 读盘版，滞后 800ms 落盘延迟）。

> 为什么：修复前反链等 4 个消费方走读盘版，其余走内存版 →
> 「刚在 A 里写了 `[[B]]`，B 的反链面板仍显示没有笔记链接到这里」，
> 且 `backLinks[absPath] ?? []` 会把「索引里还没这条」**静默显示成「真的没有反链」**。

**唯一例外**：完整性自检**必须**用 `loadIndex`（「仅载入不重建」）。
改成 `ensureIndex` 会让自检永远看不到过期索引、**诊断能力归零**。已由断言钉死。

## 三、已修复清单

### P0-1 批量替换绕过全部安全网
- **原状**：`vault/search.ts:150` 裸 `writeFile` —— 非原子写 + 无备份 + 可作用于全库，
  失败仅记软错误（磁盘满时静默半替换）。
- **现**：改三阶段 —— ① **全量预检**（不动文件，把「能不能改」前置）→
  ② **批量留档**（`backupBeforeBulkWrite`，独立 note、独立配额池、**绝不调 prune**、
  上限 200 超出则整批不备份**并明确告知**）→ ③ **顺序写 + 精确失败清单**（失败不中断）。
- 统计**只算成功**的文件：否则「A 没改成、却提示全库已替换 3 处」比静默更糟。

### P0-2 保存失败完全静默
- **原状**：`save()` 只有 `try/finally` 无 `catch`，而两条调用路径都用 `void save()`
  丢弃 rejection → 磁盘满时**用户以为已保存，磁盘上是旧版**。
- **现**：走**事件通道**（`emit('save-error')`，因 `void` 必丢 rejection），
  返回 boolean。分级打扰：**手动必弹 sticky**；**自动只亮红点 + 会话内首次提示**
  （磁盘满时每 800ms 弹一次，弹窗本身成故障源）。
- `useToast` 新增 sticky（`duration = 0`）—— 错误提示不能自己消失。

### P0-3 在途保存早退丢写
- **原状**：`if (saving.value) return` 不排队不重试 → 自动保存 A 在途时，
  定时器触发的新内容**既没写、也没人再触发**，永久留在内存。Ctrl+S 同样静默早退。
- **现**：`src/utils/saveCoalescer.ts` —— **合并而非排队** + `maxRounds=3` 硬保险 +
  超出回落 800ms 防抖。`cancelPendingSave` 同时放弃补写（冲突检测场景）。

### 🔴 附带回归（审计清单外发现，但后果最重）
`save()` 不再抛错后，原本靠 reject 中止流程的调用点**全部失效**：
「磁盘满 + 切库」= 保真层被覆盖 + 编辑器清空 = **内容只剩内存，比改造前更糟**。
→ 新增 `useSwitchGuard.saveOrAbort()`，接入 `openVault` / `openPath` / `closeTab` /
`saveFile` / `saveFileAs`（顺带修 `saveFileAs` 与 `onConflictKeepMine` 两处同类漏判）。

### P1-1 回收站静默降级为永久删除
`fsUtils.trashOrRemove` 的 `rm` 降级原记 `debug` 级（用户看不到）→ 提为 `warn` +
上报安全事件。**顺带修「最讽刺的漏洞」**：`vaultIntegrity` 的孤儿快照清理有完全相同的
`catch → rm` 降级 —— 即「一键修复」本身在静默销毁数据。

### P1-3 安全网静默失效
`readPrevContent` 原 `catch { return '' }` → 任何读取失败（EACCES/EBUSY/EISDIR）都被当成
「文件不存在」→ `shouldBackup('')` false → **跳过备份直接覆盖**。
改结构化 `{ok:true,content} | {ok:false,reason}`，区分 ENOENT（正常新建）与真读失败。

### P1-4 反链面板数据源分裂
见上方约束 2。另修一个静默错乱：文档不在索引里（刚新建/刚改名）时原本直接 `?? []` →
新文档反链面板永远空白；现先 `indexFile` 补录。

### 附带 · 崩溃残留 + 启动自检（主人指定）
- `atomicWrite` 命名改为 `.yujian-<uuid>--<目标基名>.tmp`（**带基名才能恢复**）。
- `tmpResidue.ts`：有界扫描（深度 ≤ 2、上限 200）、`pending`/`orphan` 分类、
  **恢复为副本绝不覆盖**（主人裁定）。
- `startupCheck.ts`：四项 O(1) 探针（库可写 / 回收站 / tmp 残留 / warn 软错误），
  **接线在 `VAULT_WATCH` 而非 `app.whenReady()`**（库根运行时才确定），
  `void` 启动绝不阻塞，全绿零 finding。

## 四、明确不做（及理由）

| 不做 | 理由 |
|---|---|
| 改 `atomicWrite` 三层兜底结构 | 三层是为 Windows EPERM / 云盘锁实测调出来的，重写风险大于理论窗口；待启动探针观测到 `atomicWrite.fallback` 真实频率再定 |
| 全局把 `debug` 提为 `warn` | `vault.chmod` / `index.reparse` 属正常降级，全局提级会让真正的信号被噪音淹没 |
| 自动保存失败时弹窗 | 每 800ms 一次 toast，弹窗本身成故障源 |
| 批量替换的自动回滚 | 回滚要写第二轮（新失败面）；「半批替换」是**操作未完成**而非数据损坏。已改为批前留档 + 精确清单 |
| 启动跑全库断链/损坏扫描 | 违反「自检只在显式触发时运行」铁律，大库会卡顿到不可用。已加断言钉死 |
| 改名/移动后重写正文图片引用 | 需新增图片引用解析/改写 + 大规模 fixture，工程量是其余之和 2 倍，**做错会把正文改坏**。单列一批，先只报告 |
| 调行数 / `any` 阈值 | 阈值是防劣化门禁，改它等于承认劣化。新代码全用 `unknown` + `errMsg` |

## 五、防回潮：`[Z3]` 静态门禁（24 条）

数据安全是最贵的一次性投入，若无「牙齿」钉住，半年后重构极易把某条安全网悄悄改回去。
每条断言对应一个**曾真实存在**的缺陷。两处关键修正（都是「规则自己有 bug」）：

1. **扫描前必须剥离注释** —— 否则解释旧 bug 的注释被判违规，门禁有假阳性即被当噪音无视。
2. **必须限定在函数体内断言** —— 初版用 `async function save[\s\S]*?catch\(` 跨文件搜，
   会匹配到后面别的函数，**注入故障时它没报红**（规则空转）。改用大括号配平 `extractFnBody`，
   且辅助函数须跳过签名里的默认值对象（`save(opts = {})` 的 `{}` 不是函数体起点）。
