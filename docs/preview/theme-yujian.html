玉质主题 · 材质预览

框架层用玉质与玻璃表达深度，内容层保持纯净实色。编辑区不做任何纹理与渐变——它要陪你几个小时， 任何材质都会变成视觉噪音，并且会破坏"所见即所得导出"的一致性。

深色 · 墨玉 侧栏底色 #23292B，叠加顶部微高光 + 左上青色透光 + 极细噪点

玉的关键不是绿，而是温润：光进去以后被散射开，所以颜色不均匀、边缘略亮、内部有絮状层次。 深色下用墨玉——深青灰底，只在左上和右下各留一团极淡的青色透光。

Electron 进程模型

Electron 应用由主进程、预加载脚本与渲染进程三类构成。理解它们的权限边界，是设计 IPC 通道的前提。

主进程

每个应用有且仅有一个主进程，拥有完整的 Node.js 权限，负责窗口生命周期与全部系统级操作。

TypeScript
const win = new BrowserWindow({
  webPreferences: {
    contextIsolation: true,
    nodeIntegration: false,
  },
})
注意：图床密钥必须留在主进程。打包后的渲染层脚本可被轻易反编译。
渲染进程

每个窗口对应一个独立的渲染进程，运行在 Chromium 沙箱中，不应直接接触文件系统。

浅色 · 羊脂玉 侧栏底色 #EFF2F0，编辑区 #FCFCFB（微暖白，不是纯白）

羊脂玉的特征是暖白偏一点点青，不是冷白。所以编辑区用 #FCFCFB 而不是 #FFFFFF——纯白在长时间阅读下偏刺眼。 侧栏比编辑区略深一点，让内容区"浮"起来。

必须知道的三个技术约束
1. 窗口级材质跨平台不一致。 让侧边栏真的透出桌面壁纸，需要系统 API：macOS 用 vibrancy，Windows 11 用 backgroundMaterial: 'mica' | 'acrylic'。Windows 10 及以下不支持，会自动降级为实色。 Electron 44 两者都支持，但我们必须接受"Mac 上更透，Win10 上是实色"这个现实。
  • 2. 窗口内浮层用 backdrop-filter 就够，但它只能模糊 DOM 内的元素，透不出桌面。
  • 3. 性能：backdrop-filter 在滚动和动画时开销明显。所以侧边栏用静态玉质 （渐变 + 噪点预渲染，零运行时开销），只有小面积浮层才用实时模糊。这是本方案把两者分开的核心原因。
