## 1. 设计定位

### 1.1 产品气质

这是一个**给技术写作者长时间使用的桌面工具**。设计上要克制——它不应该有存在感，用户应该忘记界面，只看见内容。

三条设计原则，按优先级排序：

1. **内容优先。** 界面元素一律低饱和、低对比，把视觉权重全部让给正文、代码与图表。
2. **可预测。** 相同操作在任何位置产生相同结果。不发明交互，沿用桌面编辑器的既有约定。
3. **克制的反馈。** 自动保存这类高频静默操作不弹提示，只在状态栏用一个色点表达。

### 1.2 明确不做

* 不做渐变、毛玻璃、阴影堆叠、霓虹光效
* 不做装饰性插画与空状态大图
* 不做会打断写作流的动画（如侧栏弹跳、按钮形变）
* 不用 emoji 作为功能图标

## 2. 布局系统

### 2.1 三栏骨架

```
┌────────────────────────────────────────────────────────────┐
│ 标题栏 38px   库名 · 文件名     [所见即所得|源码]    ─ □ ✕   │
├──────────┬──────────────────────────────────┬──────────────┤
│ 侧边栏    │  面包屑 30px                      │ 大纲 30px    │
│ 224px    ├──────────────────────────────────┤ 196px        │
│ 可拖拽    │                                  │              │
│ 180–360  │      编辑区                        │  标题层级树   │
│          │      内容列宽 720px 居中            │  滚动联动    │
│ 库切换    │                                  │              │
│ 搜索      │                                  │              │
│ 文件树    │                                  │              │
├──────────┴──────────────────────────────────┴──────────────┤
│ 状态栏 26px   字数 · 时长          ●已保存 · 行列 · 编码     │
└────────────────────────────────────────────────────────────┘
```

### 2.2 关键决策与理由

| 决策    | 值            | 理由                                                                        |
| ----- | ------------ | ------------------------------------------------------------------------- |
| 内容列宽  | **720px 居中** | 中文每行约 40–45 字，接近纸媒 reading measure（每行 45–75 字符是公认舒适区）。不限制会在宽屏上产生过长的行，导致串行 |
| 侧边栏位置 | 左侧           | 符合 Obsidian / VS Code / Typora 的既有习惯                                      |
| 大纲位置  | 右侧独立面板       | 与文件树分置两侧，避免同为"列表"的两个面板挤在一侧互相干扰                                            |
| 标题栏   | 自定义 38px     | 无边框窗口，为模式切换留出常驻位置；原生标题栏太挤                                                 |
| 状态栏   | 26px 常驻      | 保存状态、字数、光标位置是写作者的持续关注项                                                    |

### 2.3 响应式断点

桌面应用只需覆盖三种宽度：

| 宽度       | 行为                        |
| -------- | ------------------------- |
| < 900px  | 自动收起右侧大纲面板                |
| < 720px  | 自动收起左侧边栏，变为浮层             |
| ≥ 1440px | 内容列宽仍保持 720px，多余空间留白（不拉伸） |

### 3.2 排版

| 层级     | 字号   | 行高       | 字重  | 字体  |
| ------ | ---- | -------- | --- | --- |
| H1     | 28px | 1.35     | 500 | 正文族 |
| H2     | 22px | 1.40     | 500 | 正文族 |
| H3     | 18px | 1.50     | 500 | 正文族 |
| H4–H6  | 16px | 1.60     | 500 | 正文族 |
| 正文     | 16px | **1.75** | 400 | 正文族 |
| 行内代码   | 15px | 1.60     | 400 | 等宽族 |
| 代码块    | 14px | 1.60     | 400 | 等宽族 |
| UI 主文本 | 13px | 1.60     | 400 | 界面族 |
| UI 辅助  | 12px | 1.50     | 400 | 界面族 |
| 微标注    | 11px | 1.40     | 400 | 界面族 |

**正文字体栈**（中文优先，兼顾西文）：

```
-apple-system, "PingFang SC", "Microsoft YaHei", "Source Han Sans SC",
"Noto Sans CJK SC", system-ui, sans-serif
```

**等宽字体栈**（技术写作含大量中文注释，必须带中文等宽）：

```
"JetBrains Mono", "Sarasa Mono SC", "Cascadia Code",
"Menlo", "Consolas", monospace
```

> `Sarasa Mono SC`（更纱黑体）不可省——否则中文注释会因字宽不齐导致代码缩进错乱。

### 3.3 间距

基于 **4px** 基准：

```
--space-1: 4px    --space-2: 8px    --space-3: 12px
--space-4: 16px   --space-5: 20px   --space-6: 24px
--space-8: 32px   --space-10: 40px  --space-12: 48px
```

组件内部用 8 / 12 / 16px；区块之间用 24 / 32 / 48px。

### 3.4 圆角与动效

```
--radius-sm: 4px    标签、色点、徽标
--radius-md: 6px    列表项、按钮、输入框
--radius-lg: 8px    卡片、代码块、对话框
```

动效统一使用**缓出曲线**，时长分三档：

```
--ease: cubic-bezier(0.2, 0, 0.2, 1)
--dur-fast: 120ms   悬停、按下
--dur-base: 180ms   面板展开、菜单
--dur-slow: 280ms   侧栏收起、对话框
```

只允许 `opacity` 与 `transform` 参与动画（避免重排）。

**必须支持 `prefers-reduced-motion`**：该偏好开启时，全部动效时长归零。

## 5. 组件规范

### 5.1 文件树

```
▾ 技术笔记                      文件夹：12px / text-secondary
    │ electron-架构.md          选中：bg-active + 左侧 2px accent 竖条
      vite-版本锁定.md           默认：12px / text-secondary
      prosemirror-节点.md        悬停：bg-hover
▾ 随笔
```

| 项    | 规格                                                                 |
| ---- | ------------------------------------------------------------------ |
| 行高   | 28px（保证触控目标 ≥ 28px）                                                |
| 缩进   | 每级 16px                                                            |
| 展开箭头 | 9×9 三角形，点击热区扩展到整行左侧 20px                                           |
| 选中态  | `background: var(--bg-active)` + 左侧 `2px` accent 竖条（圆角 1px，内缩 6px） |
| 文件图标 | 省略——Markdown 文档统一不显示图标，靠 `.md` 后缀区分，减少视觉噪音                         |

> **为什么不给文件加图标**：技术笔记库中 95% 以上是 `.md`，图标只会重复信息。只有资源文件夹才显示文件夹图标。

### 5.2 搜索框

* 高度 28px，圆角 6px，`background: var(--bg-editor)`
* 左侧放大镜 11×11，右侧 `Ctrl K` 键位提示（11px，带 1px 边框的小胶囊）
* 聚焦时边框转 `--accent`，并出现 `0 0 0 3px` 的 10% 透明度焦点环

### 5.3 大纲面板

* 标题层级用缩进表达（H1 不缩进，H2 缩进 16px，H3 缩进 28px），**不用字号区分**——字号区分会让长标题换行
* 当前阅读位置对应项：accent 文字色 + `--bg-active` 背景
* 点击跳转，滚动时自动高亮（节流 100ms）

> ✅ **已实现**：右侧独立玉质面板（宽 `var(--w-outline)` = 196px，表头 30px 与侧栏对齐）。标题按 16px/级缩进；激活态为 accent 文字色 + `--hue-active` 背景 + 左侧 2px accent 竖条；滚动高亮复用 `ReadingProgress` 同款捕获滚动 + 100ms 节流，源码模式按 CodeMirror 首可见行比对标题行号。窗口 < 900px 自动收起（见 `src/App.vue` `outlineVisible`）。

### 5.4 状态栏

左区：字数 · 预计阅读时长
右区：保存状态（色点 + 文字）· 行列位置 · 编码

保存状态三态：

| 状态  | 色点            | 文字  |
| --- | ------------- | --- |
| 已保存 | `--success`   | 已保存 |
| 待保存 | `--warning`   | 未保存 |
| 保存中 | `--accent` 脉动 | 保存中 |

### 5.5 模式切换（标题栏分段控件）

```
┌─────────────────────────┐
│ 所见即所得 │    源码     │
└─────────────────────────┘
```

* 容器 26px 高，`background: var(--bg-editor)`，圆角 6px，内 padding 2px
* 激活段：`background: var(--accent)` + 白色文字
* 快捷键 `Ctrl + /`，在标题栏 tooltip 中标注

### 5.6 命令面板（Ctrl + K）

* 浮层宽 560px，距顶部 15vh 居中
* 输入框 40px 高，16px 字号
* 结果列表每行 36px，最多显示 9 条
* 分组标题 11px / `--text-tertiary` / 字间距 0.05em
* 支持模糊匹配，右侧显示所属分类

### 5.7 对话框

* 宽 440px（内容型）/ 520px（含列表的复杂型）
* 内边距 20px，圆角 8px，1px `--border-strong` 边框
* 标题 14px / 500，描述 12px / `--text-secondary`
* 按钮组右对齐：次要按钮在前，主按钮在后，间距 8px
* 主按钮（destructive 除外）用 `--accent` 实底 + 白字

### 5.8 标题栏功能入口与偏好设置

标题栏操作区按功能分组（分隔线 `│` 隔开）：
`打开` · `保存` · `切换工作文件夹` │ `HTML` · `PDF` │ `图床` · `外观` · `偏好设置` │ 模式分段控件。

* **切换工作文件夹**：打开系统目录选择框，无需重启即可载入另一个笔记库。切换前自动保存当前文档的
  未保存改动，并清空编辑器回到空白，文件树随即刷新为新库内容（详见架构 §5.1）。
* **偏好设置**：打开通用设置浮层（玻璃面板，宽 360px，与外观面板同款材质；浅色模式自动改用柔光玻璃），
  目前含「启动时」分组：
  * 恢复上次会话（默认）：重新打开上次使用的笔记库与文档
  * 每次启动显示全新页面：不恢复上次状态，打开即从空笔记库开始
  * 选项为单选（圆点指示器），选择即时经主进程 `patchSession` 持久化到 `session.json`，下次启动生效。

## 6. 图片资源方案（UI 落地）

存储策略详见 §7。UI 上需要三处配合：

### 6.1 移动 / 重命名文档

自动检测同名 `<文件名>.assets` 文件夹，弹出确认框（见设计稿）：

* 顶部说明："检测到同名资源文件夹，需一并移动，否则文中图片将失效"
* 文档行：源路径 → 目标路径
* 资源行：文件夹名 + 图片数量 + 总体积，右侧绿色"随行"标记
* 主按钮："一并移动"，次要按钮："取消"

**重命名时同名处理**：资源文件夹同步改名，文中相对路径自动重写。

### 6.2 断链自检

每次启动 / 切换笔记库时后台扫描（不阻塞 UI）：

* 发现失效引用 → 状态栏出现黄色标记「3 处资源失效」，点击打开修复面板
* 修复面板列出每一处：缩略图、所在文档与行号、两个操作（在库中查找同名文件 / 移除引用）
* 提供「全部自动修复」：在库内按文件名搜索，命中则改写路径

### 6.3 导出选项

导出单篇时提供两种资源模式：

| 模式        | 产出                    | 适用         |
| --------- | --------------------- | ---------- |
| 附带资源      | `.md` + 同名 `.assets/` | 归档、Git     |
| 内联 base64 | 单个 `.md`              | 粘贴到聊天窗口、邮件 |

## 10. 材质系统：玉质与玻璃

> 本节应产品方要求新增，取代 §3.1 中"扁平无纹理"的取向。
> 视觉方向参考 Apple Human Interface Guidelines 的 **Deference / Clarity / Depth** 三原则。

### 10.1 Apple 美学的真实内核

常见误解是"Apple 风格 = 毛玻璃 + 大圆角 + 渐变"。实际上 HIG 的三原则是：

| 原则                | 含义                  | 在本项目中的落实             |
| ----------------- | ------------------- | -------------------- |
| **Deference（退让）** | 界面退后，内容向前，不与内容争夺注意力 | 材质只用于框架层，编辑区保持纯净     |
| **Clarity（清晰）**   | 任何尺寸下文字都易读，装饰克制冷静   | 所有纹理对比度增量 ≤ 5%，不影响文字 |
| **Depth（深度）**     | 用层次与动效表达空间关系        | 玉质表达"框架层"，玻璃表达"浮起层"  |

**材质是表达深度的手段，不是装饰。** 这一条决定了下面的分层规则。

### 10.2 分层规则（核心决策）

| 层       | 元素                  | 材质                        | 理由                      |
| ------- | ------------------- | ------------------------- | ----------------------- |
| **框架层** | 标题栏、侧边栏、大纲面板、状态栏    | **玉质**：温润半透、极细噪点、静态渲染     | 大面积，需要稳定不晃眼；静态渲染零运行时开销  |
| **浮起层** | 菜单、命令面板、对话框、Tooltip | **玻璃**：背景模糊 + 高光边缘 + 实时模糊 | 小面积，性能可接受；模糊能表达"浮在内容之上" |
| **内容层** | 编辑区画布               | **纯净实色**，无纹理无渐变           | 见 §10.3                 |

### 10.3 为什么编辑区必须保持纯净

这是本节最重要的一条，三条理由：

1. **疲劳。** 编辑区是用户连续注视数小时的区域，任何纹理都会累积成视觉噪音。
2. **可读性。** 玉质/玻璃的半透明与色偏会直接降低文字对比度，可能突破 WCAG AA 底线。
3. **导出一致性。** 我们在架构中设计了"直取 ProseMirror DOM 导出 HTML"的方案，
   优势是所见即所得。若编辑区带材质，导出的必须是干净背景，两者观感就会脱节，
   **这个优势会被直接抵消。**

框架层加材质不影响导出——导出只取编辑区 DOM。

### 10.4 玉质配方

玉的本质是**散射**而非透视：光进入后散开，所以颜色不均匀、边缘略亮、内部有絮状层次。

**深色 · 墨玉**

```css
.jade-dark {
  background:
    /* 顶部微高光，模拟玉的边缘透光 */
    linear-gradient(180deg, rgba(255,255,255,.055) 0%, rgba(255,255,255,0) 20%),
    /* 左上青色透光 */
    radial-gradient(120% 62% at 12% 0%,   rgba(126,196,182,.13) 0%, rgba(126,196,182,0) 62%),
    /* 右下微弱反光 */
    radial-gradient(95% 55% at 85% 105%,  rgba(95,168,160,.10)  0%, rgba(95,168,160,0)  58%),
    #23292B;
}
/* 极细噪点，用伪元素叠加，避免影响盒模型 */
.jade-dark::after {
  content: ''; position: absolute; inset: 0;
  background-image: url("data:image/svg+xml,...feTurbulence baseFrequency='0.9' numOctaves='3'...");
  opacity: .045; mix-blend-mode: overlay; pointer-events: none;
}
```

**浅色 · 羊脂玉**

```css
.jade-light {
  background:
    linear-gradient(180deg, rgba(255,255,255,.85) 0%, rgba(255,255,255,0) 24%),
    radial-gradient(120% 60% at 10% 0%,   rgba(184,214,206,.42) 0%, rgba(184,214,206,0) 60%),
    radial-gradient(95% 55% at 88% 105%,  rgba(196,222,216,.34) 0%, rgba(196,222,216,0) 58%),
    #EFF2F0;
}
```

> 噪点 SVG 用 `feTurbulence` 生成 data URI，尺寸 140×140 平铺。
> 这是 Apple material 体系的标准做法，肉眼几乎不可见，但能消除"塑料感"和渐变的色带。

### 10.5 玻璃配方

玻璃与玉的区别：玉是散射，玻璃是**透视**——它需要有东西可透才有意义。

```css
/* 深色 */
.glass-dark {
  background: rgba(32, 37, 38, 0.66);
  backdrop-filter: blur(28px) saturate(160%);
  border: 1px solid rgba(255, 255, 255, 0.09);
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.07),   /* 顶部内高光 */
    0 18px 48px rgba(0, 0, 0, 0.38);
}

/* 浅色 */
.glass-light {
  background: rgba(252, 252, 251, 0.62);
  backdrop-filter: blur(28px) saturate(180%);
  border: 1px solid rgba(255, 255, 255, 0.55);
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.7),
    0 18px 48px rgba(20, 40, 36, 0.20);
}
```

**三个细节缺一不可**：

* `saturate()` 提升饱和度：纯模糊会发灰，这是"廉价毛玻璃"和"Apple material"的分水岭
* `inset 0 1px 0` 顶部内高光：模拟玻璃上沿的反射
* 1px 亮边框：定义玻璃的边界，纯色背景上尤其重要

### 10.7 技术约束（务必知悉）

1. **窗口级材质跨平台不一致。**
   让侧边栏真正透出桌面需要系统 API：

   * macOS：`new BrowserWindow({ vibrancy: 'sidebar' })`
   * Windows 11：`backgroundMaterial: 'mica' | 'acrylic' | 'tabbed'`
   * **Windows 10 及以下不支持，自动降级为实色。**

   → 必须接受"Mac 上更通透、Win10 上偏实色"的差异。**玉质配方在降级后依然成立**（渐变 + 噪点照常渲染），这正是选择"玉"而非纯玻璃的好处——它对系统能力的依赖更低。

2. **窗口内浮层用 `backdrop-filter`**，但只能模糊 DOM 内元素，透不出桌面。

3. **性能**：`backdrop-filter` 在滚动与动画时开销显著。
   → 侧边栏用**静态玉质**（预渲染，零运行时开销），只有小面积浮层用实时模糊。

4. **`prefers-reduced-motion`**：关闭动效，但材质保留（材质不是动效）。

## 11. 主题架构：材质与色相解耦

> 产品方要求：以青瓷（偏绿）打底，后续能低成本加入其他色系皮肤。

### 11.1 三层令牌

新增皮肤的成本，取决于"变的东西"和"不变的东西"分得有多干净。令牌分三层：

| 层       | 内容                          | 换皮肤时    |
| ------- | --------------------------- | ------- |
| **结构层** | 尺寸、圆角、动效时长、字体、层级透明度         | ❌ 不动    |
| **材质层** | 噪点强度、模糊半径、饱和度、高光透明度、渐变位置与角度 | ❌ 不动    |
| **色相层** | 基底色、透光色 ×2、强调色、编辑区色         | ✅ 只换这一层 |

**新增一套皮肤 = 加一段 CSS 变量块，零结构改动、零材质重做。**

### 11.2 实现：色相用 RGB 分量而非 hex

透光色需要在材质配方里以不同透明度出现多次，所以存成 RGB 分量：

```css
/* ── 材质层：所有皮肤共用，永不修改 ────────────── */
:root {
  --material-noise-opacity: .045;
  --material-noise-blend: overlay;
  --material-blur: 28px;
  --material-saturate: 160%;
  --material-highlight-top: rgba(255, 255, 255, .055);
  --material-tint-1-at: 120% 62% at 12% 0%;
  --material-tint-2-at: 95% 55% at 85% 105%;
  --material-tint-1-alpha: .13;
  --material-tint-2-alpha: .10;
}

/* ── 玉质配方：只引用变量，不写死颜色 ───────────── */
.jade {
  background:
    linear-gradient(180deg, var(--material-highlight-top) 0%, transparent 20%),
    radial-gradient(var(--material-tint-1-at),
      rgba(var(--hue-tint-1), var(--material-tint-1-alpha)) 0%, transparent 62%),
    radial-gradient(var(--material-tint-2-at),
      rgba(var(--hue-tint-2), var(--material-tint-2-alpha)) 0%, transparent 58%),
    var(--hue-base);
}

/* ── 色相层：每套皮肤一段，可随时增删 ───────────── */
[data-skin="celadon"][data-mode="dark"] {
  --hue-base: #23292B;
  --hue-tint-1: 126, 196, 182;
  --hue-tint-2: 95, 168, 160;
  --hue-accent: #5FA8A0;
  --hue-editor: #1C1E1F;
  --hue-text-1: #E8E9E7;
  --hue-text-2: #A3A7A5;
  --hue-text-3: #8B908E;
}
```

### 11.4 切换机制

* 根节点挂 `data-skin` 与 `data-mode` 两个属性，CSS 变量随之切换
* 切换皮肤**不需要重建编辑器实例**（Crepe 只读 CSS 变量，不读具体色值）
* 选择持久化在 `localStorage`（键 `yujian.appearance`，轻量、随用户、跨会话保留；见 `src/appearance.ts`）
* 提供"跟随系统"选项：`data-mode` 由 `prefers-color-scheme` 驱动（`matchMedia` 监听，实时跟随）
* 设置面板中皮肤预览用真实材质缩略图，不用色块（色块表达不出玉的质感）
* 入口：标题栏「外观」按钮 → `AppearanceSettings.vue` 弹窗（5 套材质缩略图 + 深/浅/跟随系统分段）

### 11.5 应用图标

品牌名「玉笺」，图标取**玉质圆角 tile + 笺（笔记）slip** 两层意象：

* **源文件**：`build/icon.svg`（512×512，玉质渐变 + 釉面高光 + 白色笔记 slip + 玉色文本行）
* **产线**：SVG 经 `@resvg/resvg-js`（纯 WASM）栅格化为 16/24/32/48/64/128/256/512 多尺寸 PNG，
  再按 PNG-in-ICO 格式组装为 `build/icon.ico`（Windows）；另导出 `build/icon.png`（1024，macOS / Linux）
* **接入**：
  * 开发期：`electron/main/index.ts` 的 `BrowserWindow` 设 `icon: build/icon.png`（`existsSync` 兜底，打包后回退平台默认）
  * 打包：`package.json` 的 `build` 配置指向 `build/icon.ico`（win）/ `build/icon.png`（mac/linux），由 electron-builder 注入 exe / app
* **原则**：图标只表达品牌色（青瓷玉），不随皮肤变化；皮肤切换只改应用内 CSS 变量。
